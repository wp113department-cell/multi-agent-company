1. QUESTION (#3, §1 Repository Execution): Always uses 'the repository's terminal' (real PTY/interactive terminal)
   STATUS: PARTIAL
   IMPLEMENTATION PLAN: Build a real PTY-based interactive terminal session (not just a request/response bash tool). Backend: use Python's `pty`/`ptyprocess` to spawn a real shell inside the sandbox container, keep a `PtySession` object per session in `process_manager.py`, and stream raw bytes over a new WebSocket or chunked-SSE endpoint. Frontend: add an `xterm.js` component in the chat/task UI that connects to that stream and sends keystrokes back. Reuse the existing Docker sandbox boundary (`policy/sandbox.py`) so the PTY itself still runs inside the same locked-down container, not on the host.

2. QUESTION (#5, §1 Repository Execution): Multiple terminals simultaneously (true parallel interactive shells)
   STATUS: PARTIAL  [DEPENDENT - see related item]

3. QUESTION (#6, §1 Repository Execution): Windows terminal support

4. QUESTION (#12, §17 Terminal Intelligence): Monitor streaming output (live, mid-command)
   STATUS: PARTIAL
   IMPLEMENTATION PLAN: Convert the sandboxed command execution primitive (`policy/sandbox.py::run_sandboxed()`) from a buffer-then-return `subprocess.run(capture_output=True)` model to a streaming `docker run` + incremental-read model (read stdout/stderr in a loop as it's produced, not after exit). Push each chunk out immediately as a new `terminal_output` SSE event instead of waiting for the whole command to finish. This is a security-relevant code path — change it behind a feature flag first and keep the old buffered path as fallback until it's proven stable.

5. QUESTION (#38, §59 Multi-File Operations): Preserve architecture consistency across multi-file edits
   STATUS: PARTIAL
   IMPLEMENTATION PLAN: Extend the circular-import check that `rename_symbol` already runs after itself to the other multi-file write tools (`sync_files`, `apply_patch`, batch-edit tool once #257 is built). After any tool that touches more than one Python file in one call, run `detect_circular_imports()` (already exists, reused from `architecture_reviewer`) and append an `[ARCHITECTURE CHECK]` warning block to the result, exactly like `rename_symbol` already does.
