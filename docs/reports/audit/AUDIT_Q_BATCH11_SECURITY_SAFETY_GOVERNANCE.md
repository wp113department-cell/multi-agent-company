## Summary — Batch 11 (18 checkpoints across 4 sections)

**Before this pass:** YES: 5 · PARTIAL: 11 · NO: 2
**After this pass:** YES: 15 · PARTIAL (industry-standard / honestly-scoped, not a gap): 2 · NO: 0

The 2 remaining PARTIAL checkpoints (§22 "code-level block on harmful code
categories" and half of §85 "central governance system" — the coding-
standards/naming-convention sub-scope) are PARTIAL by design, not by
omission: both were assessed as either industry-standard-consistent or
requiring an organizational decision (concrete style rules to enforce) that
doesn't exist as evidence anywhere in this repo. Building something anyway
would have meant inventing rules, which the zero-hallucination bar this
whole pass is held to explicitly forbids.

**Notable side-findings from this pass, fixed along the way:**
1. **A regression-guard test was silently checking nothing.** `test_audit05_security_fixes.py`'s `TestAllMutatingEndpointsHaveAuth` — the guard specifically meant to prevent exactly the class of gap §21 "Permission system" flagged — had been walking `app.routes` directly since a FastAPI 0.139.0 upgrade restructured `include_router` into a lazy `_IncludedRouter` tree; the naive walk saw only 21 top-level stub entries (docs/openapi/health) and 0 real routes, so it passed vacuously for an unknown period. Fixed with real route-flattening (`_iter_leaf_routes`), and now backed by a second, path-specific regression test.
2. **The interactive chat graph (`ChatAgent`) was missing three separate structural protections** that the background-agent-fleet graph (`base_graph.py`) already had: Docker sandboxing for its `bash` tool, prompt-injection wrap/flag on tool output, and a central pre-execution policy gate. All three are separate dispatch paths by design (documented, not accidental), but all three needed the same fix applied twice — found by checking both, not assuming parity.
3. **Two independently-maintained, silently-diverging secret-scanning implementations existed** (`app/agents/tools.py`'s `sec_secrets_scan` and `secrets_scan`), each with its own regex list, on top of the pre-commit scanner's own third list — consolidated onto one canonical implementation.
